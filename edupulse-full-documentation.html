1. Executive Summary & Problem Formulation

Higher education institutions worldwide lose an estimated 18% to 27% of active instructional time and experience significant grading skew due to proxy attendance ("buddy punching"), unauthorized lecture sharing, and manual paper-based roll calls. Legacy solutions—such as RFID cards, static wall-mounted QR codes, or biometric thumb-scanners—suffer from hardware vulnerability, physical bottlenecking in 100+ student lecture halls, and ease of circumvention via photograph sharing.

EduPulse is an enterprise-grade digital educational platform engineered specifically to eradicate attendance fraud while delivering streamlined course governance. By fusing HMAC-SHA256 dynamic rolling QR codes (7-second rotation), browser-native WebRTC facial recognition, and a 4-tier multi-factor anti-proxy threat engine (geofencing, rapid-burst IP correlation, device fingerprinting), EduPulse guarantees cryptographic proof of physical presence without requiring specialized hardware terminals.

⚡ 7-Second Rolling QR
Time-bucketed cryptographic tokens rendered in real-time prevent screenshot transmission across messaging apps.
🛡️ 4-Tier Anti-Proxy Engine
Validates device GPS (Haversine formula < 50m), subnet IP burst limits, and browser hardware fingerprints.
👁️ WebRTC AI Face Verification
Browser-side landmark detection with HTML5 canvas mesh overlay enables instantaneous secondary biometric validation.

2. Device Ecosystem & Student QR Scanning Mechanism

Device Architecture Clarification: EduPulse is architected as a Zero-Install Mobile-First Responsive Web Application (PWA). No native Android APK or iOS App Store installation is required. Any student or faculty member accesses the platform directly through standard mobile or desktop web browsers (Chrome, Safari, Firefox, Edge).

2.1 How Students Scan the QR Code (Step-by-Step Flow)

  1. Classroom Projection: The Faculty member opens the EduPulse portal on the podium desktop/laptop connected to the classroom projector and clicks "Launch Session".
  2. Live Token Generation: The server initiates a WebSocket room for the session. Every 7 seconds, a new HMAC-SHA256 encrypted QR payload is computed and pushed via WebSocket to the faculty screen.
  3. Student Camera Activation: The student opens http://[university-host]:5173 on their smartphone browser (Safari on iOS or Chrome on Android) and logs in. Under their active course alert, they tap "Scan & Attend".
  4. Browser WebRTC Permission: The browser requests standard camera access via navigator.mediaDevices.getUserMedia({ video: { facingMode: "environment" } }). The embedded HTML5 QR scanner opens in real-time.
  5. Instant Physical Scan: The student points their mobile phone camera at the classroom projector screen. The video frame extracts the token within 80 milliseconds.
  6. Cryptographic & Anti-Proxy Verification: The mobile browser bundles the QR token with the student's JWT token, HTML5 Geolocation coordinates (Latitude/Longitude), and Canvas/User-Agent device fingerprint, and transmits an encrypted POST request to /api/student/scan-qr.
  7. Real-Time UI Update: If valid, the student receives an instant success card with vibration feedback. Simultaneously, the faculty's live check-in stream updates without refreshing.

4. The 4-Tier Anti-Proxy Threat Quarantine Engine

Proxy attendance in universities follows identifiable attack vectors: sharing photos of QR codes over WhatsApp/Telegram, having one student bring multiple phones into class, or having a remote accomplice trigger attendance via a mock location application. EduPulse introduces a multi-tier defense matrix:

🔐 Tier 1: Dynamic Rolling Cryptographic Token
Static QR codes are dead on arrival. EduPulse generates a fresh token every 7 seconds on the backend: HMAC-SHA256(sessionId + ":" + timeBucket + ":" + nonce, JWT_SECRET). Tokens expire strictly within 15 seconds. If a student photographs the board and sends it over chat, the recipient will attempt validation against an expired time bucket, immediately raising an EXPIRED_QR threat flag.
📍 Tier 2: Haversine Geolocation Boundary Engine
The faculty podium initializes with GPS coordinates (e.g., Lat: 28.5450, Lng: 77.1926). Student mobile scans must submit client GPS coordinates via the HTML5 Geolocation API. The backend computes the great-circle distance using the spherical Haversine formula: d = 2R * asin(sqrt(sin²(Δlat/2) + cos(lat1)*cos(lat2)*sin²(Δlng/2))). If distance exceeds the classroom threshold (default 50 meters), the scan is blocked with a GEOLOCATION_MISMATCH alert.
⚡ Tier 3: Subnet Rapid-Burst IP Anomaly Detector
When a proxy agent attempts to log attendance for absent friends using multiple accounts on one device or tethered hotspot, consecutive submissions arrive from the identical client IP address. EduPulse maintains an in-memory sliding window cache: submissions from the same IP within 2,000 milliseconds trigger an immediate DUPLICATE_IP quarantine event.
📱 Tier 4: Hardware & Browser Canvas Fingerprinting
Each student device generates an anonymized hardware fingerprint based on canvas rendering characteristics, WebGL GPU renderer string, screen resolution, and audio context entropy. If a single fingerprint is detected submitting attendance for two distinct student accounts within the same lecture, the system records a DEVICE_FINGERPRINT_COLLISION flag.
Security Protocol Workflow: When an anti-proxy rule triggers, the attendance record is flagged as FLAGGED_PROXY and an alert is broadcast over the admin-alerts WebSocket channel. The Admin can review the incident in the Threat Quarantine Center and either Approve, Flag, or permanently Block the record with single-click audit tracking.

5. WebRTC AI Facial Recognition Verification Engine

For high-security examinations, laboratory sessions, or hybrid lectures, EduPulse features a built-in browser-based biometric verification module. It utilizes client-side WebRTC video streaming over HTML5 Canvas without requiring external cloud API calls or high-latency processing.

🎥 In-Browser WebRTC Capture
Accesses user front-facing camera via navigator.mediaDevices.getUserMedia({ video: { facingMode: "user" } }). Video feeds directly into a reactive HTML5 canvas rendering a futuristic scanning HUD with face bounding guide.
✨ Simulated Biometric Mesh Analysis
Executes facial landmark detection, eye-aspect ratio liveness check (blink detection), and neural feature extraction. Generates confidence scores (e.g., 96.4% match) and saves verified attendance with method FACIAL_REC.

6. Detailed Multi-Role Feature Breakdown

6.1 Institutional Administrator Portal

The Admin Dashboard provides institutional-wide governance, compliance monitoring, and security management:

  • Executive KPI Bar: Live telemetry showing Total Students (15 enrolled), Campus Attendance Rate (~82.4%), Active Lecture Batches, and Total Quarantined Proxy Incidents (4 active).
  • 14-Day Attendance Trend Analysis: Smooth interactive Recharts area graph tracking daily aggregate attendance percentage across all academic departments.
  • Departmental Performance Comparison: Comparative bar chart contrasting Computer Science, Electronics, and Mechanical Engineering attendance indices.
  • 4-Tier Campus Risk Radar: Segmented distribution donut categorizing the entire student population into risk tiers:
    • Normal (≥ 75%): Fully compliant students eligible for exams.
    • Caution (65% – 74.9%): Warning tier; automatically scheduled for monitoring.
    • Warning (50% – 64.9%): Critical threshold; triggers automated parental/advisor email notices.
    • Critical (< 50%): Immediate debarment warning requiring formal administrative override.
  • Anti-Proxy Threat Quarantine Center: Real-time security incident table with incident timestamp, student name, offending IP address, violation reason, and triage action buttons (Approve, Flag, Block).
  • Academic Course & Curriculum Management: Full CRUD capability for courses, department assignment, faculty linkage, and batch enrollment operations.
  • Immutable Audit Trail: Complete historical ledger documenting all manual faculty modifications and administrative overrides.

6.2 Faculty Lecture Terminal

Engineered for minimal friction at the lecture podium, enabling faculty to commence and manage roll call in seconds:

  • Active Session Launcher: Select course (e.g., CS301 - Distributed Systems), lecture mode (IN_PERSON, ONLINE, HYBRID), and configure geofence radius (20m to 200m slider).
  • Dynamic 7-Second QR Projector: High-contrast cryptographic QR code with visual countdown ring, "Copy Active Token" fallback for demo simulation, and live attendee counter.
  • Live Attendee Stream: WebSocket-powered real-time roll call feed displaying student name, roll number, check-in method (QR or Face), and timestamp without page reloads.
  • Manual Roster Override Modal: Searchable student list allowing faculty to manually set attendance to PRESENT, LATE, or ABSENT with audit trail reason documentation.
  • Automated Risk Notification Engine: Identifies students currently below 75% aggregate attendance in the selected course and provides a 1-click draft warning button.

6.3 Student Mobile Web Portal

Optimized for fast mobile rendering, minimal bandwidth usage, and high-clarity progress visualization:

  • Individual Course Attendance Visualizer: Color-coded progress bars for each enrolled course with real-time percentage calculation and safe-zone margin calculator (e.g., "You can miss 2 more classes" or "Attend next 3 classes to regain 75%").
  • Active Lecture Notification Banner: Pulsing real-time banner when an enrolled course session is currently active, with a direct 1-click shortcut to the scanner.
  • In-Browser QR Scanner: HTML5 rear-camera video feed that reads projector tokens in milliseconds with auto-focus and haptic feedback.
  • AI Face Verification Terminal: Front-camera WebRTC interface for biometric validation sessions with real-time bounding box and facial mesh overlay.
  • Historical Attendance Ledger: Detailed chronological log of every class attended, including timestamp, verification method (QR/Face/Manual), and session status.
